[![License: MIT](https://img.shields.io/badge/license-MIT-green)](LICENSE)

Програма для Windows, яка стежить за станом жорстких дисків (HDD) і твердотільних накопичувачів (SSD). Вона показує температуру, напрацювання, знос SSD, SMART-атрибути, заповненість розділів і активність дисків у реальному часі, а також попереджає, коли з диском щось не так.

Програма **лише читає** інформацію і нічого не записує на диски.

*In English:* DiskMonitor is a lightweight Windows 10/11 disk health monitor for HDD, SATA SSD and NVMe drives. It reads S.M.A.R.T. data and the NVMe health log, explains in plain language why a drive is considered healthy or not, tracks free space and live disk activity, and warns from the system tray when a drive's state gets worse. It only reads data and never writes to disks. The user interface is in Ukrainian.

## Можливості

- **Фізичні диски:** модель, тип (HDD, SSD, SSD NVMe), інтерфейс, обсяг, температура, напрацювання, «здоров’я» — залишковий ресурс SSD або індекс механічного стану HDD.
- **Висновок про стан** кожного диска — «Добре», «Увага» або «Погано» — з поясненням, чому зроблено такий висновок.
- **SMART-атрибути** для SATA-дисків і **журнал стану NVMe** для NVMe-накопичувачів.
- **Розділи та вільне місце** з попередженням, коли місця залишається менше 10 %.
- **Активність дисків у реальному часі:** завантаженість, швидкість читання і запису, черга запитів.
- **Робота у фоні:** програма згортається в трей, раз на хвилину перевіряє диски і показує сповіщення, якщо стан погіршився.
- **Журнал подій** і **текстовий звіт** про всі диски.
- **Автоматичні оновлення:** раз на добу програма перевіряє, чи вийшла нова версія, і встановлює її за один клік.

## Встановлення

1. Завантажте `DiskMonitor_Setup_1.4.exe` зі сторінки [Releases](https://github.com/s1xen7ag/DiskMonitor/releases/latest).
2. Запустіть інсталятор. Якщо Windows покаже вікно «Windows захистила ваш ПК», натисніть **«Докладніше» → «Виконати в будь-якому разі»**. Так буває з будь-якою програмою без платного цифрового підпису.
3. За бажанням позначте **«Запускати програму автоматично при старті Windows»** — тоді програма постійно стежитиме за дисками з трею.

**Системні вимоги:** Windows 10 або 11 (64-розрядна). Встановлювати додаткові бібліотеки не потрібно.

## Як користуватися

- **Верхня таблиця** — фізичні диски. Колонка «Стан» підсвічується кольором: зелений — «Добре», жовтий — «Увага», червоний — «Погано».
- **Подвійний клік по диску** (або кнопка «Детальніше про диск») відкриває вікно з усіма показниками, поясненням висновку і таблицею SMART-атрибутів або журналом NVMe.
- **Середня таблиця** — розділи (C:, D: …) і заповненість.
- **Нижня таблиця** — активність дисків, оновлюється кожні 2 секунди.
- **«Зберегти звіт»** — текстовий звіт про всі диски.
- **«Журнал подій»** — історія змін стану дисків (`%LOCALAPPDATA%\DiskMonitor\events.log`).
- **Хрестик** згортає програму в трей. Повністю закрити: права кнопка миші на значку → «Вихід».
- Колонка **«Здоров’я»** для SSD показує залишковий ресурс флеш-пам’яті, а для HDD — індекс механічного стану (оцінку програми, див. нижче). Прочерк означає, що диск цих даних не надає.

### Права адміністратора

Без прав адміністратора Windows не дає прочитати SMART, температуру, напрацювання і знос. Тому під час запуску програма сама просить ці права (вікно UAC). Якщо відмовитися, вона працює з обмеженим набором даних, а права можна отримати пізніше кнопкою «Перезапустити як адміністратор».

Автозапуск створюється як завдання Планувальника завдань Windows з найвищими правами, тому під час входу в систему програма отримує повні дані без вікна UAC. Перевірити: Win + R → `taskschd.msc` → завдання **DiskMonitorKursova**.

### Оновлення

Через 15 секунд після запуску, а далі раз на добу програма питає GitHub, чи вийшла нова версія. Якщо вийшла, з'являється вікно з переліком змін і кнопкою **«Оновити зараз»** (коли програма згорнута в трей — сповіщення біля годинника). Після натискання програма сама завантажує інсталятор, перевіряє його контрольну суму SHA-256, встановлює оновлення і запускається знову. Налаштування й автозапуск зберігаються. Без вашої згоди нічого не завантажується і не встановлюється.

- Перевірити вручну: **«Про програму» → «Перевірити оновлення»** або пункт **«Перевірити оновлення»** у меню значка в треї.
- Вимкнути автоматичну перевірку: права кнопка миші на значку в треї → **«Перевіряти оновлення автоматично»**.
- На GitHub надсилається лише звичайний запит про останню версію, без жодних даних про комп'ютер чи диски.
- Версії 1.0 і 1.1 оновлень ще не перевіряють, тому до версії 1.2 потрібно оновитися вручну.

## Як визначається стан диска

| Висновок | Умови |
|---|---|
| **Погано** | NVMe: критичне попередження контролера (мало резерву, знижена надійність, режим «лише читання»); SMART прогнозує відмову; Windows позначила диск як несправний; критичний (pre-failure) атрибут SMART опустився до порогу; ≥ 100 перепризначених секторів; ресурс SSD використано на ≥ 90 % |
| **Увага** | NVMe: помилки цілісності даних, перегрів; попередження від Windows; атрибут старіння (old-age) SMART досяг порогу; є перепризначені (5), нестабільні (197) або невиправні (198) сектори; температура HDD ≥ 55 °C або SSD ≥ 70 °C; ресурс SSD використано на ≥ 70 % |
| **Добре** | дані є, проблем не знайдено |
| **Невідомо** | диск не надає інформації про стан (часто USB-флешки) |

Кожен SMART-атрибут має прапорець типу: **pre-failure** (критичний — якщо він досяг порогу, диск може скоро відмовити) або **old-age** (атрибут старіння — показує знос або перевищення робочих умов). Тому поріг критичного атрибута дає «Погано», а атрибута старіння — «Увага».

**Знос SSD.** Для NVMe береться з журналу стану (Percentage Used). Для SATA SSD — з SMART, але тут атрибути не стандартизовані: той самий номер у різних виробників означає різне, а залишок ресурсу одні контролери записують у нормалізоване значення атрибута, інші — у «сире». Тому правило вибирається за виробником або за набором атрибутів, характерним для контролера (так само ресурс читає CrystalDiskInfo):

| Накопичувачі | Звідки береться залишок ресурсу |
|---|---|
| Samsung | атрибут 177, нормалізоване значення |
| Crucial, Micron | атрибут 202, нормалізоване значення |
| Intel | атрибут 233, нормалізоване значення |
| WD, SanDisk | атрибут 230: 100 мінус другий байт сирого значення |
| Toshiba, Kioxia | атрибут 173: нормалізоване значення мінус 100 |
| Kingston A400 | атрибут 231, сире значення (для прошивки 03070009 — нормалізоване) |
| Інші Kingston | атрибут 231 або 169, нормалізоване значення |
| контролери Silicon Motion (ADATA, Silicon Power, Transcend…) | атрибут 169, сире значення |
| контролери Realtek (наприклад, AGI AI138) | атрибут 169, нормалізоване значення |
| контролери Phison (Patriot, Goodram, PNY…) | атрибут 231, сире значення |
| інші | атрибут 231, нормалізоване значення |

Лічильник надійності Windows для багатьох SATA SSD повертає 0 навіть тоді, коли накопичувач знос не повідомляє, тому без підтвердження з SMART програма показує «—», а не хибні 100 %. Якщо значення є і з SMART, і від Windows, береться більший знос. У вікні деталей видно, звідки взято значення, а в таблиці SMART рядок цього атрибута позначено «Ресурс N%» і підсвічено кольором стану.

**Індекс механічного стану HDD.** Жорсткі диски не повідомляють «відсоток ресурсу»: магнітні пластини не зношуються від записів. Зате диск зношується механічно, і це видно з SMART. Індекс — це власна оцінка програми: 100 мінус штрафи за ознаки зносу. У вікні деталей показано, з яких атрибутів SMART рахується індекс і з яких штрафів він складається.

| Ознака (атрибут SMART) | Штраф | Максимум |
|---|---|---|
| Перепризначені сектори (5) | 1 за кожен | 40 |
| Нестабільні сектори (197) | 2 за кожен | 30 |
| Невиправні сектори (198) | 2 за кожен | 30 |
| Невиправні помилки читання (187) | 2 за кожну | 20 |
| Повторні спроби розкручування шпинделя (10) | 10 за кожну | 20 |
| Цикли паркування головок (193) | 10 × кількість / 300 000 | 10 |
| Запуски шпинделя (4) | 5 × кількість / 50 000 | 5 |
| Напрацювання (9) | 15 × години / 50 000 | 15 |

Якщо SMART прогнозує відмову, критичний атрибут досяг порогу або Windows позначила диск як несправний, індекс обмежується 10 %. Якщо Windows лише попереджає про проблеми — 50 %.

## Як це працює

| Простір імен WMI | Клас | Що дає |
|---|---|---|
| `root\cimv2` | `Win32_DiskDrive` | модель, серійний номер, прошивка, обсяг |
| `root\cimv2` | `Win32_LogicalDisk`, `Win32_LogicalDiskToPartition` | розділи, вільне місце, зв'язок розділ → диск |
| `root\cimv2` | `Win32_PerfFormattedData_PerfDisk_PhysicalDisk` | завантаженість, швидкість читання/запису, черга |
| `root\Microsoft\Windows\Storage` | `MSFT_PhysicalDisk` | тип (HDD/SSD), інтерфейс (SATA/NVMe/USB), стан за оцінкою Windows |
| `root\Microsoft\Windows\Storage` | `MSFT_StorageReliabilityCounter` | температура, знос SSD, години роботи, помилки |
| `root\WMI` | `MSStorageDriver_FailurePredictStatus` | прогноз відмови від самого диска (SMART) |
| `root\WMI` | `MSStorageDriver_FailurePredictData` / `Thresholds` | таблиця SMART-атрибутів і їхні пороги |

**NVMe-накопичувачі.** Журнал стану NVMe (SMART / Health Information Log, сторінка 02h) читається напряму через запит `IOCTL_STORAGE_QUERY_PROPERTY` до драйвера Windows: використаний ресурс, доступний резерв, обсяг записаних і прочитаних даних, температура, години роботи, небезпечні вимкнення, помилки цілісності даних і критичні попередження контролера.

**Оновлення.** Програма запитує в GitHub API (`api.github.com/repos/s1xen7ag/DiskMonitor/releases/latest`) відомості про останній випуск у форматі JSON: номер версії, опис змін, посилання на інсталятор і його контрольну суму (GitHub рахує SHA-256 для кожного файлу випуску сам). Запити виконуються через **WinHTTP** лише по HTTPS, а інсталятор приймається тільки з цього репозиторію. Після завантаження контрольна сума перевіряється засобами Windows (**CNG**, `BCryptHashData`), а файл лишається відкритим із забороною запису, доки інсталятор не запуститься. Якщо програма працює з правами адміністратора, інсталятор зберігається в окрему папку в `C:\Windows\Temp`, доступну лише адміністраторам і системі, тож звичайна програма не зможе підмінити файл, поки інсталятор його читає. Інсталятор запускається з параметрами `/SILENT /SUPPRESSMSGBOXES /NORESTART /UPDATE`: чекає, поки програма закриється, оновлює файли і запускає нову версію.

**Архітектура:**
- Інтерфейс написано на чистому **Win32 API** без сторонніх бібліотек, тому exe займає близько 400 КБ і не має залежностей.
- Запити WMI виконуються у **фоновому потоці**, щоб вікно не підвисало. Результати передаються у вікно повідомленнями `PostMessage`.
- Повне сканування — раз на 60 с, активність дисків — раз на 2 с (лише коли вікно відкрите).
- Якщо лічильники продуктивності Windows не працюють, активність вимірюється запасним способом через `IOCTL_DISK_PERFORMANCE`.
- Одночасно працює лише одна копія програми (іменований mutex).

## Збірка з вихідного коду

1. Встановіть **Visual Studio 2026** з набором «Розробка класичних застосунків на C++».
2. Відкрийте `DiskMonitor.sln`, виберіть конфігурацію **Release | x64** і зберіть рішення (Ctrl+Shift+B).
3. Готовий файл: `bin\DiskMonitor.exe`. Він зібраний зі статичним середовищем виконання і не потребує Visual C++ Redistributable.

**Інсталятор:** встановіть [Inno Setup](https://jrsoftware.org/isdl.php) 6.3 або новіший, відкрийте `installer\setup.iss` і натисніть Build → Compile (Ctrl+F9). Результат: `Output\DiskMonitor_Setup_1.4.exe`.

**Автоматична збірка:** після кожної зміни в репозиторії GitHub Actions сам збирає програму та інсталятор з вихідного коду ([build.yml](.github/workflows/build.yml)). Готові файли можна завантажити зі сторінки запуску в розділі **Actions → Artifacts**.

**Без Visual Studio:** встановіть [MSYS2](https://www.msys2.org/), у терміналі MSYS2 UCRT64 виконайте `pacman -S mingw-w64-ucrt-x86_64-gcc`, додайте `C:\msys64\ucrt64\bin` у PATH і запустіть `build_mingw.bat`.

## Можливі проблеми

- **Температура чи SMART показують «—».** Запустіть програму з правами адміністратора. NVMe у режимі RAID (Intel RST) або в USB-кишені може не віддавати журнал стану. У USB-флешок даних про стан зазвичай немає взагалі.
- **Порожня таблиця активності.** Лічильники продуктивності Windows вимкнені або пошкоджені. Відновити їх можна командою `lodctr /r` у командному рядку від імені адміністратора.

## Privacy policy

This program does not collect or send any information about your computer or disks. Its only network connection is a request to GitHub (`api.github.com`) about once a day to check whether a new version is available; GitHub receives only what any web request contains, such as your IP address. A new version is downloaded and installed only after you confirm it. The automatic check can be turned off: right-click the tray icon → «Перевіряти оновлення автоматично». The same is stated in the license agreement shown during installation.

Програма не збирає і нікуди не надсилає відомості про ваш комп'ютер чи диски. Єдине мережеве з'єднання — запит до GitHub (`api.github.com`) приблизно раз на добу, щоб перевірити, чи вийшла нова версія; GitHub отримує лише те, що містить будь-який запит до сайту, наприклад IP-адресу. Нова версія завантажується і встановлюється тільки після вашого підтвердження. Автоматичну перевірку можна вимкнути: права кнопка миші на значку в треї → «Перевіряти оновлення автоматично». Те саме сказано в ліцензійній угоді, яку показує інсталятор.
